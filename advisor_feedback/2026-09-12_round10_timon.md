Very nice work. Let's clean up (especially the) summary which contains
later on still the old studies and results which is a bit confusing to
me and hopefully I don't say anything wrong now :). I think we are very
close to writing the first paper :) and should structure the results a
bit. Nonetheless, a few final points:

1. You checked the N=1401 inference time versus your GPU solver which
   is the fastest among the 3 tested versions (well done :)...). It
   brings only a 10 times speed up which is rather modest at this DOF.
   I suppose this lies in the nature of the problem and a more
   challenging 3D problem such as the torsion problem of TensorMesh
   could reveal better computational advantages. Furthermore, we still
   need to report the computational details of NOs, ideally also for a
   training time and results comparison when using the finer
   resolution for integration but keep in mind that one strength of
   NOs are a) resolution invariance (train coarse, predict fine) which
   does not hold for all cases here unfortunately and b) 'decoupling'
   between parameters and resolution. So at the end we should have a
   fair comparison between a let's say below 10% smaller error at
   inference for our NO in relevant QoIs and norms versus a 'suitable'
   GPU native (coarsest) FEM simulation which achieves a comparable or
   better accuracy. This is more meaningful than comparing both
   approaches simply at the same resolution. You already checked
   selected QoIs which is perfect but the NO accuracy at N=1401 itself,
   including these QoIs has not been checked. So the 10 times speed-up
   at N=1401 is not yet an accuracy matched comparison.

2. We should also report and compare the memory and speed up for FEM
   versus NO inference. The fairest comparison is probably the bs=1
   comparison but we can add some additional explanations which would
   be in favour of NOs at inference; not at training :). It would be
   interesting to additionally report the maximum feasible batch size
   and throughput (samples/s) for both approaches at the same GPU
   memory. I expect that the NO should benefit from batching but this
   should be demonstrated.

3. I am a bit surprised how slow the NO is at inference for N=1041
   while FEM scales better. My feeling is that you optimised FEM quite
   well but there is probably still room for optimising the NO at
   inference. Could you please check this before considering the 2.29s
   as the final inference number. Can you also report the pure GPU
   forward-pass time after warm-up, excluding data transfer/
   preprocessing, the precision used and the peak GPU memory. Ideally,
   can you provide some profiling to find out where the most inference
   time is spent.

4. The tests you did are really nice and ideal for an academic paper
   but a reviewer might question the extreme fine resolution which is
   not necessary. The advantage of the NO will become crucial in
   practical problems when the geometry is complicated as the geometry
   is coupled with the parameters. I think we should add such an
   example. Ideally, this should be a problem where the fine spatial
   resolution is actually required by the geometry or physics/QoI, e.g.
   due to local stress concentrations. I'm not sure what a suitable
   example might be; could be a tire, pressure vessels with local
   details but I am flexible.

5. Last but not least, we should update the break-even analysis.

I hope that I did not miss anything :).
